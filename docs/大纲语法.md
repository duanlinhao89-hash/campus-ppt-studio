# 大纲语法

大纲是一份纯文本 Markdown 文件，分两部分：开头的**元数据**和后面的**幻灯片**。

---

## 一、元数据（可选，放在最开头）

用 `---` 包裹的 `key: value` 块：

```markdown
---
title: 我的演示
subtitle: 副标题
author: 张三 · 计算机学院
date: 2026 年 5 月
theme: academic
footer: 毕业设计答辩
section_label: 研究概述
---
```

| 字段 | 作用 |
|---|---|
| `title` | 演示标题，封面缺省时使用 |
| `subtitle` | 演示副标题 |
| `author` | 作者，封面底部信息栏显示 |
| `date` | 日期，封面底部信息栏显示 |
| `theme` | 主题 key，见 [主题与配色](主题与配色.md) |
| `footer` | 每页左下角的页脚文字 |
| `section_label` | 每个内容页右上角的栏目标签 |

命令行参数（`--theme` / `--title` / `--author` / `--date`）会覆盖这里的设定。

## 二、幻灯片

每一页用 `@布局名` 开头，之后是这一页的内容。

```markdown
@cover
# 主标题
副标题或署名

@content
## 这一页的标题
- 要点一
- 要点二
```

`#` 和 `##` 都表示标题（一页里第一个标题作为页标题）。
`- ` 或 `* ` 表示列表项。

> 如果完全不写 `@` 指令，工具会把 `##` 标题自动拆成一页页 content。
> 但为了精确控制版式，建议显式写出布局。

## 三、九种布局

### 1. `@cover` 封面

```markdown
@cover
# 基于深度学习的图像识别研究
张三 · 计算机学院
```

主色满屏背景，大标题 + 副标题，底部显示元数据里的作者与日期。

### 2. `@toc` 目录

```markdown
@toc
- 研究背景
- 方法设计
- 实验结果
```

列表项自动编号为 01、02、03…

### 3. `@section` 章节过渡页

```markdown
@section
01  研究背景与意义
为什么要做这个课题
```

主色满屏，大号章节号作背景装饰。适合分隔大章节。

### 4. `@content` 内容页

```markdown
@content
## 研究背景
- 痛点一：人工识别效率低
- 痛点二：准确率不足
```

标题 + 要点列表。要点数量会自动调整字号以适配版面。

### 5. `@two_col` 双栏对比

```markdown
@two_col
## 技术路线对比
@left
- 传统方法的特点
- 适用场景
@right
- 我们的方法
- 优势所在
```

用 `@left` / `@right` 切换左右两栏的内容。

### 6. `@stats` 数据卡

```markdown
@stats
## 核心成果
- 96.5% | 准确率
- 3.2x  | 推理提速
- 12    | 对比方法数
```

每项用 ` | ` 分隔「大数字」和「说明文字」，渲染成并排的数据卡片。

### 7. `@timeline` 时间轴

```markdown
@timeline
## 研究过程
- 2024.03 | 文献调研
- 2024.06 | 方案设计
- 2024.09 | 实验验证
- 2025.01 | 论文撰写
```

每项用 ` | ` 分隔「时间」和「事件」，渲染成水平时间轴。

### 8. `@quote` 金句页

```markdown
@quote
一句话说清这一页最重要的结论，
可以写多行。
—  study conclusion / 出处
```

淡色背景 + 大引号。`—` 开头的行作为署名。

### 9. `@thanks` 致谢页

```markdown
@thanks
## 谢谢各位老师，请批评指正
```

主色满屏，大号结束语。

## 四、小技巧

- **不确定的内容先留占位符**：用 `[括号]` 标记，生成后一眼能看到哪里还没填。
- **要点别太多**：一页建议不超过 7 条，超过后字号会自动缩小。
- **数据卡的数字越短越好**：4–6 个字符显示最大最醒目。
- **用 JSON 也可以**：程序化生成时可用 `--format json` 传入结构化 JSON，字段与上面各布局对应。
